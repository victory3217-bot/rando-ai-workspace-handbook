# CH13 저자 검토 자료 — 백업·버전 관리 기초

상태: `Draft` · `last_reviewed`: 없음 · 대상 파일: `ko/chapters/CH13.md`
작성자 자체 검토 반영(2026-10-26, Phase 3D). 저자 승인 전이며 학습자 시험은 하지 않았습니다.

> Git 사용은 요구하지 않습니다(선택·심화 과정). 파일명 버전과 변경이력표를 기본으로 합니다. 필수 실습은 연습용 가상 파일로 하며 실제 파일을 지우거나 덮어쓰지 않습니다. 클라우드 복구 기능은 공식 문서를 읽어 출처를 적었으나 모든 기능을 확인한 것은 아닙니다.

## 1. 장별 핵심 주장

1. 저장, 동기화, 백업, 버전 기록은 서로 다르다. (일반 설명 + 저자 해석)
2. Google Drive for desktop에서 휴지통에 넣은 파일은 미러링·스트리밍 시 모든 곳에서 휴지통에 들어가며(S14), 수정은 양쪽에 자동 동기화된다(S11). 그래서 동기화는 백업이 아니다. (공식 문서 + 저자 해석)
3. Google Drive 휴지통은 30일 뒤 영구 삭제, `Empty trash`는 즉시 영구 삭제(S14). (공식 문서)
4. Google Drive 파일의 이전 버전은 가장 최근 것만 저장되며 `Keep forever`로 보관(S15), Google 문서류와 다른 파일의 버전 기록은 다르다(S15). (공식 문서)
5. OneDrive는 삭제·덮어쓴 파일을 개인 30일, 직장·학교 93일 이내(관리자 변경 제외) 복원할 수 있고, 영구 삭제 후와 공유받은 파일은 복원할 수 없으며, Microsoft 365 구독자는 이전 버전과 전체 되돌리기를 쓸 수 있다(S13). (공식 문서)
6. 비개발자에게는 파일명 버전 + 변경이력표 + 따로 둔 백업을 기본으로 권한다. (저자 제안)
7. 백업 규칙(두 벌, 동기화되지 않는 곳, 정기, 복원 시험, 등급 준수, 날짜 기록)은 교육용이며 조직 규정이 우선이다. (저자 제안)
8. 지침서·지식 변경은 한 번에 하나, 시험 후 확정, 이전 버전 보관, AI 프로젝트에도 같은 버전 반영. (저자 제안)

## 2. 교육목표

저장·동기화·백업·버전 기록 구분, 원본과 사본, 파일 버전관리, 변경이력, 복구 순서, 클라우드 휴지통·버전 기록의 한계, 백업 규칙, 지침서·업무자료 변경관리.

## 3. 실습과 완료 기준

| 실습 | 구분 | 하는 일 | 완료 기준 |
|---|---|---|---|
| 1 | 필수 | 후보 A 폴더 백업 계획 | 폴더, 제외, 동기화되지 않는 장소, 주기, 담당, 복원 시험 |
| 2 | 필수 | 파일 버전관리 규칙 | 버전 올리는 때, 최종본 표시, 이전 버전 위치 |
| 3 | 필수 | 지침서 변경이력표 | v01·v02 내용, 이유, 확인, AI 프로젝트 교체 |
| 4 | 필수 | 복구 점검표 | 상황별 멈춤·찾을 곳·확인·기록 |
| 5 | 필수 | 가상 파일로 복원 연습(`연습_가상`, `연습_백업`) | 복원 결과 기록 |
| 6 | 선택 | 클라우드 휴지통·버전 기록 확인(가상 파일) | 확인한 것/못한 것 구분 |

산출물 4개: 후보 A 업무 폴더의 백업 계획, 파일 버전관리 규칙, 지침서 변경이력표, 복구 점검표.

## 4. 출처가 필요한 주장

| 본문의 주장 | 출처 | 상태 |
|---|---|---|
| 수정이 컴퓨터와 Drive에 자동 동기화 | S11 | 원문 확인 |
| 휴지통 파일은 미러링·스트리밍 시 모든 곳에서 휴지통에 들어감, 공유받은 사람은 영구 삭제 전까지 접근, 휴지통도 저장 공간 차지, 30일 뒤 영구 삭제, 소유자 영구 삭제 시 공유받은 사람도 접근 상실 | S14 | 원문 확인 |
| 이전 버전은 가장 최근 것만(`Keep forever`), 활동에서 변경 확인, Google 파일과 다른 파일의 버전 기록 차이 | S15 | 원문 일부 확인(절차 본문은 접혀 있어 읽지 못함) |
| OneDrive 복원 기간, 영구 삭제 후 복원 불가, 공유받은 파일 불가, Microsoft 365 구독자의 이전 버전 복원 | S13 | 원문 확인 |

**한계:** OneDrive 설치·동기화 설정과 버전 기록 세부 조건, Google Drive `Keep forever` 외 보관 개수, Google 문서류 버전 기록 상세, Windows 휴지통 세부 동작, 요금제·조직 계정 차이는 읽지 않았고 본문에도 적었습니다. 문서 날짜는 표시되지 않았습니다. **수업 직전에 S11, S13~S15를 다시 읽어야 합니다.**

**저자 해석:** 동기화≠백업 판단, 파일명 버전 우선 권고, 복구 순서, 백업 규칙 6가지, 변경관리 절차.

## 6. 예상 실습시간과 미검증 사항

- **예상 시간** 필수 약 60분, 선택 약 20분. 저자의 예상이며 시험하지 않았습니다.
- 미검증: 학습자가 백업 계획을 실제로 지키는지 / 복원 연습이 이해에 도움이 되는지 / 변경이력표가 부담스럽지 않은지 / 서비스 화면이 본문과 같은지.

## 7. 강사용 예상 질문과 오류 대응 (초안, 사용해 본 적 없음)

| 예상 질문·상황 | 대응(안) |
|---|---|
| "클라우드에 있으면 백업 아닌가요?" | 삭제와 수정이 퍼질 수 있고(S11, S14) 휴지통·복원에는 기간이 있다(S14, S13). 따로 둔 복사본과 복원 시험이 필요 |
| "Git을 써야 하나요?" | 필수 아님. 선택·심화 과정에서 다룬다 |
| "회사 자료를 어디에 백업하나요?" | 조직 규정을 확인. 확인 전에는 "확인 필요" |
| "휴지통을 비웠어요" | 서비스로는 어렵다(S14, S13). 백업과 이전 버전 파일을 찾는다 |
| "버전 번호를 깜빡해요" | 공유 전에 올리는 규칙으로 정하고, 서비스 버전 기록의 조건을 확인 |
