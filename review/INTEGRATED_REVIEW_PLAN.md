# CH01~CH14 통합 검토 계획

작업 문서(교재 본문이 아니며 사이트에 게시되지 않음). 작성 2026-10-26. **계획이며 아직 실행하지 않았습니다.** 모든 장은 `Draft`이고 `last_reviewed`는 비어 있습니다. 이 계획의 어느 단계도 저자 승인이나 학습자 시험이 이미 이루어졌다는 뜻이 아닙니다.

## 0. 범위와 전제

- 대상: 한국어 필수 과정 CH01~CH14(기본 범위). 선택·심화 OP01~OP03은 `Planned`로만 두고 이 계획에 포함하지 않는다. Git·GitHub, Claude Code, 하네스 엔지니어링은 향후 별도 교육과정으로 분리한다.
- 교육대상: 비개발자 일반 실무자. 후보 업무 A 하나를 CH01에서 CH14까지 이어 가는 누적형 실습 구조를 유지한다.
- 검토 원칙: 임의로 재작성하지 않는다. 수정은 저자 결정 → 최소 수정 → 변경 이력 기록 순서로 한다. 상태(`Reviewed` 등)와 `last_reviewed`는 **저자가 직접** 바꾼다.

## 2. P0·P1. 저자 검토 순서와 초점

한 번에 14장을 읽기 어려우므로 네 묶음으로 나눈다. 묶음마다 *앞 장 산출물이 뒤 장에서 실제로 쓰이는지*를 함께 본다.

| 묶음 | 장 | 저자가 특히 볼 것 |
|---|---|---|
| ① 개념과 보안 | CH01~CH03 | 세 개념(워크스페이스·Workflow·하네스) 정의, 후보 선정 기준(1차 세 질문), 정보 등급 A/B/C(법적 분류 아님, 조직 규정 우선), 공식 출처 S1~S5 |
| ② 환경 구축 | CH04~CH07 | 폴더 구조·파일명 규칙, 동기화≠백업, ChatGPT·Claude 프로젝트 설정(공식 출처 S6~S13), 계정이 없을 때의 대체 경로 |
| ③ 활용 | CH08~CH11 | 지식베이스 구조, 사실·추론·가정·미확인 구분, 지침서 8요소, Workflow 승인 지점, 공개 하네스 사례(CH10) |
| ④ 완성 | CH12~CH14 | 검증 절차와 재실행 판단 기준, 백업 규칙, 완성 수준 Level 1~3과 실행 구분 |

**저자가 결정할 사항의 모음(장별 5절에서 추림):**
1. 정보 등급의 3단계 구조와 예시(CH03). 법무·정보보안 검토를 받을지.
2. 필수/참고 학습 구분과 6시간 워크숍 구성(`WORKSHOP_6H_PLAN.md`).
3. 하네스 사례를 CH02와 CH10에서 같은 저장소(rando-promotion-harness)로 두는 것의 중복, 다른 공개 사례를 추가할지.
4. 재실행 2회 권고, 심각도 정의, 백업 주기, 승인 지점 기준 등 *저자의 교육용 기준*을 유지할지(CH11~CH13).
5. 완성 수준 Level 1~3의 조건과 자기 평가 방식(CH14).
6. 영어 번역을 시작할 시점과 순서(한국어 장이 `Reviewed` 이상이어야 함).

## 4. P3. 공식 출처·하네스 사례 재확인

- 방법: 브라우저로 원문을 다시 열어 각 장이 인용한 문장이 그대로인지 확인하고, 바뀌면 본문·9절 표·`source-map.md`를 함께 갱신한다. **수업 직전(하루 전)에 반드시 반복한다.**
- 미확인 항목(OneDrive 설치·동기화 세부, 한국어 화면 메뉴 이름, 프로젝트 지침 글자 수 제한, 올린 파일의 자동 갱신 여부 등)은 필요하면 추가로 읽는다.
- 하네스 사례: rando-promotion-harness(CH02, CH10), rando-client-discovery-harness(CH03)의 공개 여부와 커밋 일치를 재확인한다(`gh repo view`, `git ls-remote`). 비공개 저장소는 쓰지 않는다.

## 6. P5. 학습자 시험(파일럿) 설계안

**지금까지 학습자 시험은 한 번도 하지 않았다.** 모든 소요 시간과 "도움이 된다"는 판단은 작성자의 추정이다.

| 항목 | 안 |
|---|---|
| 대상 | 비개발자 일반 실무자 3~5명(계정 있는 사람, 없는 사람 혼합) |
| 방식 | 6시간 워크숍 구성안으로 실제 진행(관찰자 1명) |
| 관찰 항목 | 각 실습의 시작·종료 시각, 막힌 곳, 질문, 화면이 본문과 다른 곳, 대체 경로 사용 여부, 가상 자료 사용 여부 |
| 측정 | 장별 실제 소요 시간, 완료 기준 달성 여부, 도달 수준(Level 1~3) |
| 사후 | 이해하기 어려웠던 용어·표, 양식이 번거로운 곳, 불필요한 부분 |
| 기록 | 관찰 기록을 `review/` 작업 문서로 남기고 장별 6절(예상 실습시간과 미검증 사항)을 *측정값*으로 갱신. 측정 전에는 효과를 주장하지 않는다 |
| 안전 | 가상 자료만 사용. 조직 자료는 조직 허용 확인 후 참가자 본인이 결정 |

## 7. P6. 수정과 상태 결정

1. 시험·검토에서 나온 수정은 우선순위(오해·안전 → 막힘 → 표현)로 정해 **최소 수정**한다. 큰 재작성은 저자가 따로 승인한다.
2. 장별로 저자가 8절에 검토 결과를 쓴다. 승인하는 장만 저자가 `content-manifest.json`의 `status`와 `last_reviewed`를 직접 바꾼다. 도구나 AI가 대신 바꾸지 않는다.
3. 영어는 한국어 장이 `Reviewed` 이상이 된 뒤 시작한다. 영어 번역은 이 계획의 범위 밖이다.
4. `CHANGELOG.md`에 검토 사실을 적는다.

## 8. 알려진 한계(검토 때 함께 판단)

- 클립보드 복사 버튼의 실제 동작은 일반 브라우저에서 확인되지 않았다(`README.md` 참조). 404 페이지 빌드 경고가 있다(동작에 영향 없음으로 판단, 저자 확인).
- 복사용 양식이 많아 학습자가 직접 만들 *가상 파일 묶음*과 배포용 양식 모음이 아직 없다. 다운로드 제공 여부는 저자 결정(현재 사이트에 다운로드 기능 없음).
- 한국어 화면 메뉴 이름을 확인하지 못한 제품 기능이 많다(ChatGPT·Claude·Google Drive·OneDrive).
- 감사 도구는 구조·형식 검사이며 학습 효과를 검증하지 않는다.
