# CH11 저자 검토 자료 — 반복 업무와 AI Workflow 설계

상태: `Draft` · `last_reviewed`: 없음 · 대상 파일: `ko/chapters/CH11.md`
작성자 자체 검토 반영(2026-10-26, Phase 3C). 저자 승인 전이며 학습자 시험은 하지 않았습니다.

> 코드 없이 종이, 문서, 글자 도표로 작성합니다. **하네스 구축 실습은 포함하지 않았으며 선택·심화 과정으로 미룹니다.** 이 장은 공식 문서를 인용하지 않습니다.

## 1. 장별 핵심 주장

1. 업무 절차는 순서이고, AI Workflow는 그 순서에 담당(사람/AI), 입력·출력, 확인, 예외 처리를 더한 설계다. (이 책의 작업 정의)
2. 세 개념(워크스페이스, Workflow, 하네스)은 배타적 분류가 아니라 연결·포함될 수 있다. 업계 표준이라고 단정하지 않는다. (CH01 정의 유지)
3. 입력 → 처리 → 검증 → 출력 구조와 결정 지점을 흐름도로 그린다. (저자 설계)
4. 밖으로 나가는 것, 되돌리기 어려운 것, 판단·책임이 필요한 것, 자료를 AI에 넣기 전, AI가 확신이 없을 때는 사람의 승인 지점으로 둔다. (저자의 제안)
5. 예외 처리표, 표준 실행 절차, 실행 체크리스트, 실행 기록으로 반복 업무를 표준화한다. (저자 설계)
6. 시간이 줄었는지는 이 책이 확인한 사실이 아니라 학습자가 기록으로 확인할 일이다. (본문에 명시)
7. 단순 Workflow와 하네스의 차이는 초점과 구성의 차이이며, 둘은 서로 활용·포함할 수 있다. (작업 정의)

## 2. 교육목표

업무 절차와 Workflow의 관계, 입력→처리→검증→출력, 승인 지점, 실패·예외 처리, 표준 실행 절차, 실행 기록과 개선, Workflow와 Harness의 차이, 후보 A Workflow 작성.

## 3. 실습과 완료 기준

| 실습 | 구분 | 하는 일 | 완료 기준 |
|---|---|---|---|
| 1 | 필수 | 업무 흐름도 | 입력·처리·검증·출력, 결정 지점, 중단 조건 |
| 2 | 필수 | 단계별 실행 절차 | 단계마다 담당·입력·작업·남기는 것·다음 조건 |
| 3 | 필수 | 사람의 승인 지점 | 이유, 승인자 역할, 확인할 것 |
| 4 | 필수 | 예외 처리표 | 6개 이상 |
| 5 | 필수 | 실행 체크리스트 | 시작 전·실행 중·끝난 뒤, 한 장 |
| 6 | 선택 | 시험 실행 1회와 실행 기록(AI 없이 대체 가능) | 기록 한 줄 |

산출물 5개: 업무 흐름도, 단계별 실행 절차, 사람의 승인 지점, 예외 처리표, 실행 체크리스트.

## 4. 출처가 필요한 주장

공식 문서·하네스 사례 인용 없음. 모두 이 책의 작업 정의 또는 저자 해석입니다.

| 주장 | 비고 |
|---|---|
| Workflow, 하네스의 정의 | CH01의 작업 정의와 `glossary.md`에 맞춤. 외부 문헌 검토 전 |
| 승인 지점 기준, 예외 처리표 예, 월 1회 검토 권고 | 저자 제안. 시험하지 않음 |
| 흐름도 표기(네모, ◆, 화살표) | 이 책의 약속 |

## 5. 저자의 의사결정이 필요한 항목

| # | 결정할 것 | 작성자의 권고 |
|---|---|---|
| 1 | 하네스 구축을 완전히 선택·심화로 미룬 것 | 요청대로 유지. 본문은 "출발점"까지만 언급 |
| 2 | 승인 지점 기준 5가지 | 시험 후 조정 |
| 3 | 흐름도를 글자 도표로 제공하는 방식 | 접근성 때문에 글자 도표 유지. 이미지는 영어판·대체 텍스트 비용이 늚 |
| 4 | 하네스 사례를 CH11에 추가할지 | 현재 CH10 사례를 가리킴. 추가 사례는 공개 확인 후 저자 결정 |
| 5 | "책임은 사람" 입장 | CH09와 같은 표현. 법무 검토 없음 |

## 6. 예상 실습시간과 미검증 사항

- **예상 시간 75분.** 저자의 예상이며 시험하지 않았습니다.
- 미검증: 학습자가 흐름도를 그릴 수 있는지 / 다른 사람이 문서 묶음만 보고 업무를 할 수 있는지 / 승인 지점 기준이 적절한지 / Workflow가 실제 업무를 개선하는지 / 시험 실행 시간.
