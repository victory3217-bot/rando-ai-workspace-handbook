# CH08 저자 검토 자료 — 개인 지식베이스 구축

상태: `Draft` · `last_reviewed`: 없음 · 대상 파일: `ko/chapters/CH08.md`
작성자 자체 검토 반영(2026-10-26, Phase 3C). 저자 승인 전이며 학습자 시험은 하지 않았습니다.

> 마스터노트 같은 전문 지식체계를 필수 전제로 삼지 않았습니다. 필수 실습은 AI 서비스 없이 가능하며, 실습 6(AI 프로젝트에 올리기)만 선택이고 설계서로 대체할 수 있습니다.

## 1. 장별 핵심 주장

1. 업무 파일은 일하며 생기는 것이고, 지식베이스는 반복해서 쓰려고 정리한 자료다(출처·갱신일·인덱스). (저자 해석)
2. 자료를 원본자료, 요약, 업무 규칙, 근거자료로 구분한다. (저자 분류)
3. 후보 A 지식 폴더는 `04_AI지침과양식/지식`(인덱스, 업무규칙, 양식과예시, 용어와기준, 출처기록)이다. (저자 설계)
4. 지식문서마다 출처, 갱신일, 다시 확인할 시점을 적고, 오래된·충돌 정보는 상태 표시와 충돌 기록으로 사람이 처리한다. (저자 제안)
5. 프로젝트에 올린 파일은 그 시점의 사본일 수 있어 원본 변경 시 다시 올려야 한다고 가정한다. 자동 갱신 여부는 확인하지 않았다. (저자 해석)
6. ChatGPT 프로젝트의 파일 수 한도, 같은 이름 파일 처리, 응답 저장, Google Drive 동기화 미지원과 Claude 프로젝트 지식·파일 한도. (공식 S6, S8, S10)

## 2. 교육목표

업무 파일과 지식베이스 구분, 네 종류 구분, 폴더·인덱스 정리, Markdown 지식문서, 출처·갱신일, 오래된·충돌 정보, AI 프로젝트에서의 활용.

## 3. 실습과 완료 기준

| 실습 | 구분 | 하는 일 | 완료 기준 |
|---|---|---|---|
| 1 | 필수 | 후보 A 지식 폴더 만들기(새 폴더만) | 하위 폴더 존재 |
| 2 | 필수 | 자료를 네 종류로 분류(이름·종류만) | 모든 자료 분류 |
| 3 | 필수 | 지식문서 1개(가상 메모 → K01) | 목적, 범위, 출처, 갱신일, 확인 시점, 등급 |
| 4 | 필수 | 자료 인덱스 | 모든 문서 등록 |
| 5 | 필수 | 출처·갱신일 기록, 가상 충돌 처리 | 확인일, 충돌 결정 기록 |
| 6 | 선택 | 프로젝트에 인덱스·K01 올려 사용(또는 설계서) | 올릴 파일, 합치는 계획, 지침 문장 |

산출물 4개: 후보 A 지식 폴더, 자료 인덱스, 지식문서 1개, 출처와 갱신일 기록.

## 4. 출처가 필요한 주장

| 본문의 주장 | 출처 | 상태 |
|---|---|---|
| ChatGPT 프로젝트 파일 수 한도(5/25/40), 같은 이름 파일 `Upload anyway`/`Skip`, `Add to project sources`, Google Drive 앱이 프로젝트에서 동기화 미지원 | S6 | 원문 확인 |
| Claude 프로젝트 지식은 모든 대화에서 쓰이고 대화 간 맥락은 지식에 넣은 것만 공유 | S8 | 원문 확인 |
| Claude 프로젝트 파일 30MB, 개수 무제한이나 컨텍스트 한도, 텍스트 추출 | S10 | 원문 확인 |

**한계:** 올린 파일이 원본 변경 시 자동 갱신되는지, ChatGPT 프로젝트 파일 크기·형식 한도, 한국어 화면 메뉴 이름은 읽지 않았고 본문에도 적었습니다. 폴더 구조, 네 종류 구분, 충돌 처리 순서, 문서 틀, 상태값은 저자의 교육용 설계입니다. **수업 직전에 S6, S8, S10을 다시 읽어야 합니다.**

## 5. 저자의 의사결정이 필요한 항목

| # | 결정할 것 | 작성자의 권고 |
|---|---|---|
| 1 | 지식 폴더를 `04_AI지침과양식/지식` 아래 두는 설계 | 유지. CH04의 폴더 구조와 맞춤 |
| 2 | 네 종류(원본/요약/규칙/근거) 구분 | 유지. 학습자에게 어려우면 규칙과 근거를 합치는 안 가능 |
| 3 | 문서 틀의 항목 수(10개 안팎)가 비개발자에게 많은지 | 시험 후 조정 |
| 4 | 마스터노트 등 기존 방식 사용자에게 안내 | 본문에 "이미 쓰는 방식 유지" 안내함 |
| 5 | 충돌 처리 순서(공식 지침 → 최신 → 권한자) | 저자 확인. 조직 규정이 우선이라고 적음 |
| 6 | 프로젝트 사본 개념(자동 갱신 단정 금지) | 유지. 공식 문서로 확인되면 수정 |

## 6. 예상 실습시간과 미검증 사항

- **예상 시간 60분(실습 6 별도 약 15분).** 저자의 예상이며 시험하지 않았습니다.
- 미검증: 학습자가 네 종류를 구분하는지 / 인덱스·출처기록 관리 부담이 현실적인지 / K01 작성이 가상 메모에서 자연스러운지 / 프로젝트에 올린 지식이 AI 결과에 영향을 주는지.

## 7. 강사용 예상 질문과 오류 대응 (초안, 사용해 본 적 없음)

| 예상 질문·상황 | 대응(안) |
|---|---|
| "저는 노션/옵시디언을 써요" | 도구를 바꾸지 않는다. 네 종류 구분, 출처·갱신일, 인덱스만 가져간다 |
| "마스터노트를 꼭 만들어야 하나요?" | 아니다. 폴더 하나, 목록 한 장, 문서 한 개로 시작 |
| "파일을 올리면 AI가 자동으로 최신으로 아나요?" | 이 책은 확인하지 않았다. 사본으로 보고 바뀌면 다시 올린다 |
| "회사 규정 문서를 올려도 되나요?" | CH03 등급과 조직 규정을 먼저 확인. 이 장은 가상 자료만 |
| "충돌하는 문서는 AI가 판단하게 해도 되나요?" | 사람이 정하고 기록한다 |
