# Glossary

A table matching Korean and English terms. It records only terms actually used in this handbook, and it does not define new concepts here for the first time. Entries marked "working definition" are this book's own teaching definitions, not external standard definitions. Entries marked "design proposal" are provisional definitions for curriculum design and will be refined after a later literature review. Terms whose meaning is official or external (for example, a product's own feature names or a legal term) are not defined here; check the official source or your organization's rules.

| Term | Korean | Definition / note |
|---|---|---|
| AI Workspace | AI 워크스페이스 | Working definition: a work environment for carrying out work together with AI. An environment in which materials, AI tools, connections, access permissions, instructions, and human roles are organized (not limited to a physical space or a folder; "place" and "desk" are metaphors). It is not the same concept as the word "workspace" used in services such as ChatGPT. It may overlap with AI Workflow and AI Harness |
| AI Workflow | AI Workflow | Working definition: a concept that focuses on the steps and procedure for carrying out work. Verification or exception handling steps may be included in it. It may overlap with AI Workspace and AI Harness |
| AI Harness | AI 하네스 | Working definition: an execution system that supports and controls AI so that it carries out a specific task. It may include execution rules, tools, procedures, input and output conditions, verification criteria, and exception handling. It is not an exclusive category next to workflow and workspace; they can be connected or include one another. It is not asserted as an industry-standard definition |
| AI tool · AI service | AI 도구 · AI 서비스 | How this book uses them: AI tool is a broad term for anything that lets you use AI functions; AI service is the part of it, such as ChatGPT or Claude, that reads text and writes new text |
| Component | 구성요소 | CH02 design proposal (five components): PC and local files, cloud storage, AI work environment, work documents and knowledge base, work instructions and confirmation records |
| Work instructions | 지침서 | A document that states the work rules AI follows. Chapter-by-chapter explanation is in CH10 (planned) |
| Knowledge base · Index | 지식베이스 · 인덱스 | CH08: a collection of material organized for repeated work, with sources and update dates recorded / a list of where those documents are and what kind they are. It does not have to be a grand system; it can start with a folder and one list |
| Source material · Summary · Work rule · Evidence | 원본자료 · 요약 · 업무 규칙 · 근거자료 | CH08 design proposal (the author's classification): as received / shortened and organized / an agreement on how to do the task / material that shows why a rule is the way it is |
| Fact · Inference · Assumption · Unconfirmed | 사실 · 추론 · 가정 · 미확인 정보 | CH09: content that can be confirmed in the source text / a judgment drawn from facts / a premise set without confirmation / information not yet known to be true. Write only facts in the final output and mark the rest |
| Work instructions (work instructions document) | 업무 지침서 | CH10: a reusable document with purpose and scope, input conditions, execution steps, output format, prohibitions, exception handling, verification criteria, and revision log. Project instructions in AI services (CH06, CH07) are one form of it |
| Approval point · Exception handling | 승인 지점 · 예외 처리 | CH11: a place where a person must judge or approve directly / what to do when things do not go according to the set procedure |
| Verification checklist · Two-way comparison | 검증 체크리스트 · 양방향 대조 | CH12: a list of the items to check in a result, written in advance / comparing in two directions: result to source text (finding fabrications) and source text to result (finding what is missing) |
| Severity · Re-run | 심각도 · 재실행 | CH12 design proposal (the author's teaching criteria): how big an error is (high, medium, low) / asking the AI again with the same work instructions and material |
| Sync · Backup · Version history | 동기화 · 백업 · 버전 기록 | CH13: making several places match (deletions can spread too) / a copy kept separately / earlier states that a service keeps (conditions and periods differ by service). Sync is not backup |
| Change log | 변경이력표 | CH13: a table that records, for each document, the version, date, what changed, the reason, the check result, and the location of the previous version |
| Simulated run · Live AI run | 가상 실행 · 실제 AI 서비스 실행 | CH14: a run-through with fictional material and fictional output (no request to AI) / a request made to a real AI service. Runs with fictional data and runs with approved work data are marked separately |
| Completion level (Level 1 to 3) | 완성 수준 Level 1~3 | CH14 design proposal (not a certification standard; a self-assessment): design complete / environment set up / work executed and verified |
| Information tier | 정보 등급 | CH03 design proposal (not a legal classification): A information that may be entered / B information to enter only after masking / C information not to enter |
| Transmission · Retention · Training use | 전송 · 저장 · 학습 | CH03: input arriving at the provider, how long records remain, and use for improving a model are separate questions |
| General explanation · Official documentation check · Author's interpretation | 일반 설명 · 공식 문서 확인 · 저자 해석 | How the text is labeled: text without a label is a general explanation / an **Official documentation check** box holds what was confirmed in official product documentation (source number and check date required) / **Author's interpretation** marks classifications and judgments the author made for teaching |
| Harness case | 하네스 사례 | A supporting case that shows the design principle of a chapter. Only repositories confirmed to be public are used, and the repository, file path, what was confirmed, status, and verified-on date are written together |
| Core study · Reference study | 필수 학습 · 참고 학습 | A distinction used in CH03 (the author's suggestion). If time is short, do only the core study and read the reference study when needed |
| Knowledge Base | 지식베이스 | A collection of material you have organized for repeated work, with a list so you can find things and a record of where each item came from and when it was last checked; an organized folder counts (added for the English glossary; defined in CH08) |
| Project Instructions | 프로젝트 지침 | Directions to the AI service that apply only inside that Project (ChatGPT Projects and Claude Projects); one form of work instructions (added for the English glossary; defined in CH06 and CH07) |
| Source Material | 원본자료 | Material exactly as you received it; do not edit it, and keep it in the `01_Originals` folder (added for the English glossary; defined in CH08) |
| Verification | 검증 | Checking the AI's result against the source text with a checklist written in advance, because AI can make up content, get numbers wrong, or leave things out (added for the English glossary; defined in CH12) |
| Exception Handling | 예외 처리 | What to do when things do not go according to the set procedure, for example when material is missing; written as a table of "in this situation, do this" (added for the English glossary; defined in CH10 and CH11) |
| Version Management | 버전 관리 | Putting a version in the file name (`v01`, `v02`), making revisions one at a time with the reason and date in a log, and keeping the previous version before finalizing a new one (added for the English glossary; defined in CH10 and CH13) |
| Backup | 백업 | A copy kept separately somewhere else in case a file is lost or damaged; it does not change along with the original, so it is different from sync (added for the English glossary; defined in CH04, CH05, and CH13) |
| Human Approval | 사람의 승인 | A place (human approval point) where a person must judge or approve directly, such as going outside, hard-to-undo actions, or decisions needing responsibility; this book's principle is not to hand these points over to AI (added for the English glossary; defined in CH11) |
