## 2. Core Concepts

**Terms used in this chapter**
- **File**: One item of material saved on a computer. A document, a table, a photo, and so on.
- **Folder**: A box that holds files. You can put folders inside folders.
- **File extension**: The part at the end of a file name, such as `.docx` or `.pdf`. It tells you the type of the file.
- **Path**: An address that says which folders a file is in. Example: `Documents\AI_Work\10_TaskA_MeetingMinutes\03_Final`.
- **Original**: The file you first received or first created, which you do not touch.
- **Working copy**: A file you make by copying the original and then edit. **Final version**: The file that is confirmed and shared or submitted.
- **Version**: A number that tells apart each edit of the same file. You write it like `v01`, `v02`.
- **Backup**: A *copy kept separately somewhere else* in case a file is lost or damaged. It is different from sync, which keeps the same file matched in several places (CH05).

### 2-1. Files, folders, and file extensions

The foundation of an AI Workspace (CH01) is *knowing where you have put your own material*. When you give material to an AI service, you upload a file or paste text. If you do not know which file it is, you cannot give it, and if you do not know which one is the latest, you will give the wrong material.

The file extension decides *which program opens the file*. Changing the extension does not change the contents of the file, so if you only rename a `.docx` to `.pdf`, it will not open. When you rename a file, be careful not to delete the extension.

### 2-2. Using Windows File Explorer

File Explorer is the standard program in Windows for viewing files and folders. You open it by pressing `Windows key + E` on the keyboard or by clicking the folder icon on the taskbar. (The screens may differ a little depending on your Windows version.)

| What you want to do | How |
|---|---|
| Go into a folder | Double-click the folder |
| Go up one level | Click the up arrow button, or click the name of the upper folder in the address bar |
| Create a new folder | In an empty area, right-click → New → Folder |
| Rename | Click the file once, press the `F2` key, and type the name |
| Copy | Select the file and press `Ctrl + C`, then press `Ctrl + V` in the folder where you want to paste |
| Show file extensions | In the top menu, open `View`, then `Show` (or the `View` tab), and turn on `File name extensions` |
| Check the path | Look at the address bar at the top |

**Always keep file extensions turned on.** Then you can tell `report.docx` and `report.pdf` apart, and you will notice the mistake of deleting the extension while renaming.

### 2-3. Comparing file formats

| Format | Extension | What kind of file it is | Where it is used at work |
|---|---|---|---|
| TXT | `.txt` | A file with plain text only and no styling. Opens in Notepad | Memos, rule notes, text to copy and paste |
| Markdown | `.md` | A text file that shows structure with symbols such as `#` for headings and `-` for lists. Also opens in Notepad | Instructions and templates to give to AI |
| Word | `.docx` | A document with editing formatting such as fonts, tables, and pictures | Reports, meeting minutes, notices |
| PDF | `.pdf` | A document whose appearance is fixed. Usually for reading | Final versions for submission or sharing |
| Excel | `.xlsx` | A table with calculations and table formatting | Lists, totals, calculations |
| CSV | `.csv` | A simple table whose columns are separated by commas. Opens in Excel | Exchanging table data without formatting |

> **Author's interpretation** *Instructions and templates* to give to AI are easier to handle as files without formatting, such as TXT or Markdown, while *outputs and submission copies* are more convenient as Word or PDF. However, the file formats and limits that each AI service can read differ, so you will check which formats work in each service's official documentation in CH06 (ChatGPT) and CH07 (Claude). This chapter does not say whether any specific service supports a format.

### 2-4. Designing a work folder structure

**Principles (the author's suggestion):** ① Divide folders *by task*. ② Keep the depth to about three levels. ③ Put a number in front of each name to fix the order. ④ Build folders of the same kind with the same structure for every task.

Here is an example of a standard structure for candidate A.

```text
AI_Work/
  00_Guide/                                 ← usage rules for this structure, file-naming rule
  10_TaskA_MeetingMinutes/
    01_Originals/                           ← as received, not touched
    02_Working/                             ← where you copy originals and edit them
    03_Final/                               ← confirmed files that you share
    04_AI_Instructions_and_Templates/       ← corresponds to boxes ④ and ⑤ of CH02
    05_AI_Output_and_Verification_Log/      ← AI drafts and the record of what you checked
    09_Do_Not_Give_to_AI_(Tier_C)/          ← material you judged as C in CH03
  20_TaskB_/                                ← candidate B, built with the same structure
  90_Archive/                               ← finished work
```

How this relates to the five boxes of CH02: `01_Originals` to `03_Final` are the *work files* of ① (PC and local files), and `04_AI_Instructions_and_Templates` is the *starting place* for ④ (work documents) and ⑤ (work instructions). You will fill this place in CH08 (knowledge base) and CH10 (work instructions).

> **Author's interpretation** The `09_Do_Not_Give_to_AI_(Tier_C)` folder is only a *device that makes the material visibly separate so that you do not upload it by mistake*, and it is not a security control. There is no guarantee that material will not be uploaded to AI just because you put it in the folder, and your organization's rules come first for how Tier C material is actually handled (CH03).

### 2-5. File-naming rule and version control

**An example rule (the author's suggestion):**

```text
[date]_[task]_[content]_[version].extension
2026-10-12_SalesMeeting_Minutes_Q3_v01.docx
```

- Write the date first, in the order `year-month-day`. When you sort by name, the files line up by date.
- Raise the version as `v01`, `v02`. Instead of writing `final` in the file name of a final version, put it in the `03_Final` folder or add `_approved`.
- Add `_AI_draft` to drafts made by AI to tell them apart from files made by people.
- The characters `\ / : * ? " < > |` cannot be used in Windows file names. Beyond that, many spaces and special characters can cause problems in other programs, so we recommend joining words with `_`.

Names to avoid: `minutes_final.docx`, `minutes_really_final(1).docx`, `New Document.docx`. You cannot tell which one is the last or what the content is.

### 2-6. Original, working copy, and final version

```text
01_Originals (as received)  →  copy  →  02_Working (files you edit, v01, v02...)  →  approve  →  03_Final (files you share)
```

- You do not edit the original. It is the place you can go back to when you edit something wrongly.
- Whenever possible, give AI *a copy or a masked file, not the original* (CH03).
- Keep what AI produces (`_AI_draft`) in `05_AI_Output_and_Verification_Log`, and send only what a person has checked and corrected through `02_Working` to `03_Final`.

### 2-7. Basics of file search and backup

**Search:** If you type part of a name in the search box at the top right of File Explorer, it searches inside the current folder. If you have a file-naming rule, you can find files by typing just `SalesMeeting` or `2026-10`. To search by extension, type something like `*.docx`. How to search the whole computer instead of one folder, and the filter screen, differ depending on your Windows version.

**Backup basics (general explanation):** The basic rule is to keep important files *in two or more different places*. Another folder on the same computer is easy to lose together with the rest if the computer breaks. **You cannot know whether a backup works until you restore from it once.** Cloud storage and sync are covered in CH05, and more detailed methods of backup and version management are covered in CH13.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| You cannot see `.docx` at the end of the file name | Showing file extensions is turned off | Turn on `File name extensions` using the method in section 2-2 |
| The file will not open after you renamed it | You deleted or changed the extension | Add the original extension back to the end of the name. The original extension is the format of the program that made the file |
| It says you cannot rename the file | The file is open in another program | Close the program and try again |
| You do not know where you saved a file | You saved it without looking at the save location | Type part of the name in the search box. From now on, choose the folder yourself when you save |
| A folder name is too long and copying fails | If the path is too long, some programs can have problems | Shorten the folder names and reduce the depth |
| You deleted a practice file by mistake | Deletion | Restore it from the Recycle Bin. If you emptied the Recycle Bin, these are fictional files, so create them again. **This chapter does not delete real files** |
| All the candidate A materials are Tier C | Candidate A depends on sensitive material | Follow the guidance in CH03 to switch to fictional data, or go back to CH01 and choose a different candidate |
