## 1. Learning Objectives

When you finish this chapter, you will be able to do the following.

- Explain, in one final workspace map, how the components of your AI workspace connect to each other.
- Re-evaluate the work purpose from CH01 and organize the scope and rules of candidate A into one set of documents.
- Check the information security standards (CH03) and your folders, Project, work instructions, and workflow before you run.
- Run candidate A (as a simulated run or a live AI service run), then verify and record the result using the method from CH12.
- Put error handling and backup and operating rules into the final documents.
- Honestly determine the **completion level (Level 1 to 3)** you have reached, with evidence.

## 2. Core Concepts

**Terms used in this chapter**
- **Connection check table**: A table for checking that the deliverables from earlier chapters connect to each other.
- **Pre-run check**: Checking the material tier, the tool, the work instructions, and the human approval points before you run the work.
- **Simulated run**: Following the work from start to finish with fictional material and a fictional AI output (or a person standing in for the AI). You did **not** send a real request to an AI service.
- **Live AI service run**: Sending a real request to a real AI service and receiving the result. In this book, you do this *only with allowed material*.
- **Completion level**: The three stages this book defines (Design complete / Environment set up / Work executed and verified).

### 2-2. Re-checking the candidate task and the purpose of working with AI

The *purpose of working with AI* that you set in CH01 was your first goal. Now evaluate it **only as far as your records allow**.

- Is the purpose (for example, reduce the burden of repetitive document work) still the right one?
- Are the inputs, outputs, and things a person must check for candidate A the same as at the start, or have they changed?
- Do your run log (CH11) and error log (CH12) contain times or error counts that *you measured yourself*?

> **Author's interpretation** If there is no record, do not write "time went down" or "errors went down." This book has not confirmed those effects either. The honest evaluation when there is no record is: "Not measured yet. We will record it starting with the next run."

### 2-3. Checking local and cloud folders

Check that the folder structure from CH04 actually exists, that the file naming rules are followed, that the cloud folders and sharing permissions from CH05 follow the rules, that no Tier C folder has been uploaded, and that each original is in only one place.

### 2-4. Checking work material and information security standards

**Do the pre-run security check *before* you run the work.** Check that the input material for candidate A is at the CH03 tier (A, or masked B), that your organization allows the AI service and account you will use, that there is no personal information, password, or API key, and that you have not shared the Project or turned on external connections. If even one answer is "no," *do not do a live AI service run*. Substitute a simulated run.

### 2-5. Checking the AI Project and knowledge material

Check that the Project in CH06 and CH07 contains the latest work instructions (CH10 v02 or later), that the knowledge files you uploaded have the status `valid` (CH08), the number of uploaded files and the limit, the memory setting, the name and description (Claude cannot see the name and description), and where the instructions are placed. An uploaded file may be a copy from that moment, so check the *upload date* (CH08).

### 2-6. Checking the work instructions and the workflow

Check that the run steps in the work instructions (CH10) and the steps in the workflow (CH11) are in the same order, that the verification criteria match the checklist in CH12, that human approval points come before any step that sends something outside, and that the versions are the same (the change log table in CH13).

### 2-7. Running the real work and verifying the result

The run follows this order. At every step, record the **run type**.

```text
Pre-run check (2-4) → Run (CH11 procedure) → Verify (CH12 checklist) → Re-run / fix / confirm (CH12 decision table) → Approve (CH11 approval point) → Save and record (CH04, CH13)
```

| Run type | Meaning | Label |
|---|---|---|
| Simulated run | Done with fictional material. No request was sent to AI, or a fictional AI output was used | `[Simulated run]` |
| Live AI service run (fictional data) | A request was sent to an AI service with *fictional data* | `[Live AI run: fictional data]` |
| Live AI service run (approved work data) | A request was sent with *real work material* that your organization allows and that has passed the tier check | `[Live AI run: approved work data]` |

Do not swap these three labels. Do not call an AI run on fictional data a "real work run."

### 2-8. Error handling and backup and operating plan

The operating rules include the following: what to do when an error occurs (CH12 decision table), who approves (CH11), when and how to check and change the work instructions and knowledge (CH13 change management), the backup schedule and restore test (CH13), and when to re-check the official documentation and service settings (screens and policies can change).

### 2-9. Completion level assessment

> **Author's interpretation** The three levels below are defined by this book for teaching and are not a certification standard. Even participants who cannot do a live run because of account or organization installation limits **can reach Level 1.**
>
> | Level | Name | Completion conditions |
> |---|---|---|
> | **Level 1** | Design complete | The following exist *as documents*: ① final workspace map, ② work purpose and scope, ③ folder and material management rules, ④ AI Project settings (a design sheet is acceptable), ⑤ work instructions, ⑥ work workflow, ⑦ verification checklist, ⑧ backup and operating rules. They agree with each other in the connection check table (record any mismatches), and you can explain the candidate A task from the documents alone. A simulated run may be included |
> | **Level 2** | Environment set up | Level 1 + you actually set things up in the tools available to you: you actually created the local folders / where available, the cloud folder and the AI Project (instructions entered, fictional material uploaded) / you passed the pre-run security check / you did one backup and restore with fictional files / you finished *preparing to run with fictional material* |
> | **Level 3** | Work executed and verified | Level 2 + you did *real work* with AI using **allowed material** (a service and account your organization allows; CH03 tier A or masked B) (`[Live AI run: approved work data]`), and you have the CH12 verification checklist, an error log, and a human final confirmation record, and you made a backup |
>
> **Labeling rule:** Write only the highest level you have reached, together with its *evidence documents*. **Never mark a person who completed Level 1 as having completed Level 3.** Running AI on fictional material alone is not Level 3. If even one condition of a level is missing, do not write that you reached that level. Write "working toward the next level" instead.
>
> This assessment is the *learner's self-assessment* and is not verified by the author or an instructor. Whether this level structure helps learning has not been tested.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Deliverables from earlier chapters are missing | You skipped some chapters | Fill in with the fictional example for that chapter and mark `[Fictional example]`. If many boxes are marked, you are assigned a lower level |
| The connection check table shows many mismatches | Each chapter was changed separately | Pick one standard (the work instructions) and align the rest to it. Record each change in the change log table (CH13) |
| You cannot use an AI service | No account, or organization policy | Use Path B (simulated run) and aim for Level 1. This is not a failure |
| You are not sure whether you may use real work material | Permission has not been confirmed | Do not use real work material. Ask the person in charge, and use fictional material until it is confirmed |
| You ran AI on fictional material and want to call it Level 3 | You confused the level criteria | Level 3 is when you do and verify *real work with allowed work material*. A run on fictional material goes only up to Level 2 |
| You want to write down an effect (such as time saved) | There is no record | Write only what your records show. If there is none, write "not measured yet" |
| The pre-run check came out "no" | A security, approval, or version problem | Stop the live AI run, fix the cause, and check again |
| Personal information appeared during verification | It was mixed into the input material | Stop using it, tell the person in charge, and delete that conversation (CH03 Section 7) |
| Screens or policies changed after you finished | Services change from time to time | On the re-check date in your operating plan, check the official documentation and your own screen again, and reflect changes in the work instructions and Project settings |
