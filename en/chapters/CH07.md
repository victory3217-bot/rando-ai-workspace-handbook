## 2. Core Concepts

**Terms used in this chapter**
- **Project**: a workspace in Claude that has its own chat history and knowledge material.
- **Project knowledge**: material you have uploaded to a Project. It is used in every conversation in that Project.
- **Project instructions**: directions to Claude that apply to every conversation in that Project.
- **Claude Desktop**: an app that you install on your own computer to use Claude.
- **RAG (retrieval-augmented generation)**: a method for large amounts of material in which the AI finds and uses the relevant parts instead of reading everything. The official documentation introduces it as an expanded capability on paid plans.

### 2-1. Basic ways to use Claude

You can use Claude in a web browser, in a desktop app, and on mobile (`[S8]` describes memory on the web, in Claude Desktop, and on mobile). After you sign in, you can start a *chat*, ask questions, and upload files. A file uploaded to a chat is used only within that chat, while material uploaded to a Project is used in every conversation in the Project.

### 2-2. The concept of Claude Projects

> **Official documentation check — Claude Projects, checked on 2026-10-26**
>
> - A Project is a self-contained workspace with its own chat history and knowledge base, where you can upload documents, give context, and have focused conversations. `[S7]`
> - Projects are available to all users, including free accounts, and free users can create up to 5 Projects. `[S7]` `[S8]`
> - Knowledge uploaded to a Project is used in all conversations in that Project, and Project instructions apply to all conversations in the Project. `[S7]` `[S8]`
> - On paid plans (Pro, Max, Team, Enterprise), Project knowledge capacity expands through RAG when it nears the limit. This expansion exists only on paid plans. `[S7]`
> - A new version of Projects (beta) is being rolled out in stages, starting with some Pro and Max users, and the documentation says that in the new version a Project works like a single conversation. This document describes the current version. `[S7]`

### 2-3. Creating and configuring a Project

> **Official documentation check — Creating and managing Projects, checked on 2026-10-26**
>
> - You create a Project at `claude.ai/projects` by selecting `+ New Project` and entering a name and description. **Claude cannot see the name and description.** `[S8]`
> - Project knowledge is on the right side of the Project page, and you upload documents, text files, and code snippets with the `+` button. `[S8]`
> - For Project instructions, select `Set project instructions`, type them in, and save with `Save instructions`. `[S8]`
> - Context is not shared between the conversations in a Project; only what you put in Project knowledge is shared. `[S8]`
> - Each Project has its own memory. Inside a Project, the Project's memory and your memory from outside the Project are used together, but memory from other Projects is not used. To separate Project memory completely, turn off `Use account memory` under `Memory` on the Project page. `[S8]`
> - Memory is on by default on the web, in Claude Desktop, and on mobile for Free, Pro, and Max. For Team and Enterprise, the owner must turn it on. `[S8]`
> - A Project can be archived or deleted. Archiving keeps the sharing permissions and knowledge as they are; an archived Project cannot be deleted, so you must unarchive it first. `[S8]`
> - On Team and Enterprise, you can share a Project with members of your organization (`Can view`, `Can edit`), and administrators can turn sharing off. Personal accounts do not have this sharing feature. `[S7]` `[S8]`

> **Author's interpretation** It matters that *Claude cannot see the name and description*. Write a Project's purpose and rules in the **instructions**, not in the name or description. If you want a Project to stand on its own, turning off `Use account memory` is recommended for learning purposes (the official documentation only explains how and does not recommend it).

### 2-4. Project instructions and knowledge material, using files and work material

> **Official documentation check — Uploading files and limits, checked on 2026-10-26**
>
> - Supported document formats are PDF, DOCX, CSV, TXT, HTML, ODT, RTF, EPUB, JSON, and XLSX, and XLSX can be uploaded only when code execution and file creation are turned on. Supported image formats are JPEG, PNG, GIF, and WebP. `[S10]`
> - Files can be uploaded to an individual chat or to the files area of a Project so that they can be used across all conversations in the Project. `[S10]`
> - Chat uploads are limited to 500MB per file and a maximum of 20 files per chat. `[S10]`
> - Project files are 30MB per file with no limit on the number of files, but the whole content must fit in Claude's context window, and only text is extracted (except multimodal PDFs). `[S10]`
> - For non-PDF documents such as DOCX, only text is extracted, and images inside the document cannot be read. `[S10]`

| Where you upload | Where it is used | Use it when |
|---|---|---|
| Chat | Within that chat | Material you use only once |
| Project knowledge | All conversations in the Project | Templates, rules, and reference material you use every time |

**How to divide instructions and knowledge (the author's suggestion):** Put *rules to always follow* (role, output format, no guessing) in the instructions, and *material to read and refer to* (a blank template, a term list) in the knowledge. This is the same as separating instruction files from template files inside the `04_AI_Instructions_and_Templates` folder in CH04. In this chapter, you upload *the meeting notes that change every time* to the chat and keep *the blank template* in the knowledge.

### 2-5. Differences between Claude Desktop and the web

> **Official documentation check — Claude Desktop, checked on 2026-10-26**
>
> - Claude Desktop is available on macOS, Windows, and Linux (beta), and Windows requires Windows 10 or later. `[S9]`
> - On Windows, you download the Windows version from the Claude download page, open the installer, launch it from the Start menu, and sign in. `[S9]`
> - Chat is available on all plans including Free, while Claude Code and Claude Cowork are available on paid plans (Pro or higher). `[S9]`
> - Claude Cowork is described as a feature that directly accesses local files in a folder the user has connected and handles multi-step tasks, with reading and writing limited to the connected folder. `[S9]`

| | Web | Claude Desktop |
|---|---|---|
| Installation | Not needed | Needed `[S9]` |
| Chat, Projects | Available `[S7]` | Chat is available `[S9]`. This book did not check whether the Project screen is the same as on the web |
| This book's required exercises | The web is enough | Optional |
| Local file access (Cowork) | Not applicable | A paid-plan feature, and not part of this book's required exercises `[S9]` |

> **Author's interpretation** Start with *the web, which needs no installation*. A feature such as Claude Cowork that accesses your folders *widens the material the AI can reach once you turn it on*, so it is treated only as an option, and only after you check the tiers in CH03 and your organization's rules. Claude Code and CLI-based harness development are covered in this book's optional and advanced courses and are not required exercises in this chapter.

### 2-6. Personal information and organizational account policies

Material you upload to a Project also follows *the tiers and rules of CH03* as they are. How data is used for model training differs between personal plans (Free, Pro, Max) and business plans (Team, Enterprise, API, and so on). For that content, look again at the Official documentation check boxes in CH03 (`[S3]`, `[S4]`, `[S5]`). This chapter does not repeat it.

> **Official documentation check — Personal-plan training conditions (rechecked from CH03), checked on 2026-10-26**
>
> - On personal products (Free, Pro, Max), conversations can be used for training in cases such as when the user allows model improvement, and Incognito chats are not used for model improvement. `[S3]`

**What this chapter sets (the author's judgment):** ① Do *not share* the Project. ② Do *not turn on* external connections, Claude Cowork, or folder access. ③ Upload fictional data only. ④ Do not write personal information, passwords, or API keys in the Project's name, description, or instructions. This book did not read when Project files are erased from the servers after you delete them in the official documentation, so it does not state that as fact.

## 7. Troubleshooting

| Symptom | Cause | How to fix it |
|---|---|---|
| `Projects` or `+ New Project` does not appear | Your screen is the new version, or your account, plan, or organization settings differ `[S7]` | Follow the description on your own screen. On an organizational account, ask your administrator; if that does not work, use the alternative path (design sheet) |
| You cannot create more Projects on free | Free is limited to 5 `[S7]` | Clean up Projects you do not need (to delete one, unarchive it first `[S8]`) or reuse one |
| Claude does not follow a rule you wrote in the Project name | Claude cannot see the name and description `[S8]` | Write the rule in the instructions |
| A new chat does not know the contents of an earlier chat | Between chats in a Project, only what you put in knowledge is shared `[S8]` | Upload anything you will keep using to Project knowledge |
| An XLSX file will not upload | Code execution and file creation must be turned on `[S10]` | This chapter does not turn them on, so convert the file to CSV or TXT |
| Claude does not know what a picture inside a file shows | Non-PDF documents have only their text extracted `[S10]` | Write the contents of the picture out as text |
| A message says the file is too large | Project files are limited to 30MB `[S10]` | Split or shrink the file |
| Contents of another Project get mixed in | Memory setting `[S8]` | Turn off `Use account memory` and open a new chat inside the Project |
| You uploaded material you should not have | You uploaded it before checking the tier | Do not hide it. Tell the person in charge, and delete the file and the conversation. For when it is erased from the servers after deletion, see the `[S4]` (chat deletion) explanation in CH03, and tell the person in charge that this book has not confirmed this for Project files |
