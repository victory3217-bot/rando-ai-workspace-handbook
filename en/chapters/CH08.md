## 2. Core Concepts

**Terms used in this chapter**
- **Knowledge base**: a collection of material that you have *organized* for repeated work. It has a list so you can find things, and it records where each item came from and when it was last checked.
- **Index**: a list of which documents are in the knowledge base and where. It works like the index of a library.
- **Source material**: material exactly as you received it (the `01_Originals` folder in CH04).
- **Summary**: the content of the original, shortened and organized.
- **Work rule**: an agreement about how this task will be done.
- **Evidence material**: material that shows why a work rule is the way it is (contracts, guidelines, official documentation, and so on).
- **Markdown**: a way of marking headings and lists in a text file (`.md`) with symbols such as `#` and `-` (CH04).
- **Update date**: the date the contents of that document were last checked or edited.

### 2-1. The difference between work files and a knowledge base

| | Work files | Knowledge base |
|---|---|---|
| What it is | Files that come up as you work (meeting notes, deliverables) | Material organized for repeated use |
| Form | Different each time | A set format, a list, and naming rules |
| Source and date | Often missing | Always recorded |
| Who uses it | The person who made it | You, coworkers, and AI services |
| Example | `2026-10-12_SalesMeeting_Notes_v01.txt` | The `Minutes Writing Rules` document and the index that points to it |

### 2-2. Purpose and components

**Purpose:** to stop explaining the same thing again and again, and to build a *reliable reference* to give AI. There is one question: "What do I need to know to do this task, and where is the evidence for it?"

**Components:** ① an index (what is where), ② knowledge documents (rules, terms, template descriptions), ③ source material or its location, ④ a record of sources and update dates. These correspond to ④ (work documents and knowledge base) and ⑤ (work instructions and confirmation records) in CH02.

> **Author's interpretation** A knowledge base is not a grand system. *One organized folder, one list, and one document* are enough to start. Specialized knowledge management methods such as a master note are not a required prerequisite in this book. If you already use a method, keep it and take only the distinctions and records below.

### 2-3. Source material, summary, work rule, and evidence material

| Type | Description | Example (candidate A) | Caution |
|---|---|---|---|
| Source material | Exactly as received | Meeting notes, a PDF of past minutes | Do not edit it. Check its tier (CH03) |
| Summary | A shortened version of the original | A summary of decisions from the past 3 months of meetings | Note which original it came from, and mark it if AI made the summary |
| Work rule | An agreement we made | "If there is no owner or deadline, write 'Needs confirmation'" | Who decided it, when, and whether there is evidence |
| Evidence material | The reason for the rule | The company's document-writing guidelines, an email with the manager's instruction | Source and date |

**Why separate them:** A summary can differ from the original, and a rule without evidence later loses its reason to be followed. If you keep them separate, AI can tell whether something is "an original, something someone shortened, or an agreement."

### 2-5. Knowledge documents written in Markdown

You need only a few symbols. Write in Notepad and save as `.md`.

```text
# Title              ← large heading
 ## Subheading
- Item               ← list
1. Numbered item
| Column 1 | Column 2 |       ← table
|---|---|
| value | value |
**bold**
```

**Knowledge document template (the author's suggestion):**

```text
# [Document title]
- Document no.: K01
- Type: rule / summary / evidence / term
- Purpose: one line on what this document is for
- Scope: which tasks it applies to
- Source: where the content came from (source number or description)
- Update date: 2026-10-26
- When to check again: (for example, when the rule changes, or 3 months later)
- Tier: A / B

 ## Content
(for a rule, short numbered items)

 ## What needs confirmation
(what you do not know, what you have not yet confirmed)

 ## Related documents
```

### 2-6. Managing sources and update dates

In every knowledge document, record the **source, update date, and when to check again**. If there is no source, write "No source (author's judgment)," and do not mix judgment with fact. For a summary made by AI, mark "AI draft, checked by a person / not yet checked." Collect these records in one table in `90_Source_Log.md`.

```text
Document | Source | Date of source | Date I checked | Checked by | When to check again
```

### 2-7. Outdated and conflicting information

| Situation | How to handle it |
|---|---|
| A rule has changed | Raise the document to `v02` with the new rule, change the status of the old document to `retired`, and keep it in `90_Archive`. Do not delete it |
| Two documents disagree | Mark both `needs review`, leave a *conflict record*, and have a person decide. Do not give them to AI before the decision |
| The date is old | When the time to check again has passed, change the status to `needs review` |
| The source is unknown | Mark it `no source` and do not use it as a rule |

**Order for resolving a conflict (the author's suggestion):** ① the organization's official guidelines, if any; ② whichever was confirmed more recently; ③ the judgment of the person with decision authority. Whatever the order, *a person decides and records it*, and you do not leave it to AI. The organization's rules come first.

### 2-8. Using knowledge material in AI projects

If you upload knowledge documents to the projects you made in CH06 and CH07, they can be used as reference material in that project's conversations.

> **Official documentation check — uploading material to a project, checked on 2026-10-26**
>
> - In a ChatGPT project you can upload PDFs, spreadsheets, documents, and images, or paste text, and the number of files you can upload depends on the plan (Free 5, Go and Plus 25, Edu, Pro, Business and Enterprise 40). `[S6]`
> - When you upload a file with the same name in ChatGPT, it asks you to choose `Upload anyway` or `Skip`. `[S6]`
> - You can save a ChatGPT response to the project sources with `Add to project sources` and reuse it. `[S6]`
> - In ChatGPT projects, the Google Drive app does not support sync even when added to a project; you can search and access it, but its contents are not synced in advance. `[S6]`
> - Claude project knowledge is used in all conversations in the project, and among the conversations in a project, only what you put in project knowledge is shared as context. `[S8]`
> - Claude project files are limited to 30MB per file, there is no limit on the number of files, but the whole content must fit in the context window, and only text extraction is done. `[S10]`

> **Author's interpretation** These are the judgments this book draws from the facts above. ① Treat an uploaded file as *a copy from that point in time*. After you edit the original document, think of the file in the project as something you must upload again or replace, and do not assume it becomes up to date automatically (whether it updates automatically is not something this book has confirmed). ② Because there is a limit on the number of files, upload fewer documents by combining them, such as *1 index + a few rule documents + 1 template*. ③ If you put "Do not write anything that is not in the knowledge; when you do, write the document number" in the instructions (CH10), verification becomes easier. ④ Before uploading, check the document's tier (CH03) and that its `status is valid`.

## 3. Workplace Application

Gasang Han at the fictional company Example Trading Co. kept getting the same questions while repeating the minutes task (candidate A). "What format were the minutes in?" "How do I write the deadline?" (All fictional.)

| Before | After |
|---|---|
| Rules are scattered across messenger chats and personal notes | One `Minutes Writing Rules` (K01) document and an index were made |
| Nobody knows who decided them or when | The document records the source (manager's instruction note) and update date |
| Deadline notation differs between documents ("next week," "10/20") | Both documents were marked `needs review`, the manager was asked, one was chosen, and the old document was marked `retired` |
| The rules had to be explained to AI again each time | The rule document was uploaded to the project and "write the rule document number" was added to the instructions |

The effects (such as how much time was saved) are not something this book has confirmed; they are fictional expectations. No harness case is used in this chapter.

## 7. Troubleshooting

| Symptom | Cause | How to fix it |
|---|---|---|
| A `.md` file does not open in Notepad | A different program is associated with it | Right-click the file, choose the "Open with" menu (Korean-language screen name: 연결 프로그램; check your own screen), and pick Notepad |
| You cannot tell whether something is a summary or an original | You did not record the source | Write in one line where it was made from. If you do not know, leave it as `no source` and do not use it as a rule |
| There are so many rules that the document gets long | Several purposes are mixed in one document | Split the documents by purpose. But consider the file-count limit for AI projects, and combine what should be combined |
| There are two documents with the same content | A copy was made | Keep one, mark the other `retired`, and move it to `90_Archive` |
| The rule uploaded to the project is an old one | An uploaded file may be a copy from that point in time `[S6]` | Upload a new version of the file in its place (if the name is the same, follow the on-screen instructions `[S6]`) and record the update date |
| AI writes things that are not in the knowledge | The instructions have no restriction | Add "Do not write anything that is not in the knowledge" to the instructions, and have a person check (CH10, CH12) |
| The number of files exceeds the limit | There is a file-count limit by plan `[S6]` | Combine documents or remove the less important ones |
| A document that must not be uploaded is in the index | It was registered before its tier was checked | Mark that document's status `do not upload` and confirm with the person in charge (CH03) |
