## 1. Core Concepts

### 1-1. What structure should a work request to AI have

If a request is vague, the result is vague. A **work request** is writing that hands a task to AI. It is a kind of prompt; in this book it means a request that has a defined structure. If you include the six parts below in the request, it is easy to carry over into the work instructions in CH10.

**① Purpose** says why you are doing this task. For example: "Create a draft of the meeting minutes to reduce the organizing burden."

**② Input material** says what you give AI and the tier of that material. For example: "Masked fictional meeting notes (B)."

**③ Task** says the work AI must do. For example: "Organize decisions, owners, deadlines, and open items in a table."

**④ Output format** says the shape, items, and length of the result. For example: "Table + 'Needs confirmation' list, within one page."

**⑤ Rules** say what AI must not do and what it does when it does not know. For example: "Do not write anything that is not in the notes; mark it 'Needs confirmation.'"

**⑥ How to check** says what the person will check. For example: "Whether decisions, owners, and deadlines match the notes."

### 1-2. Defining input material and expected output

When you define the input material, write down three things: whether you checked its tier from CH03, which version it is (CH04 file-naming rules), and what it contains and what is missing.

When you define the expected output, also write down three things: who will use it, which items are required, and what the AI will not do (making decisions on someone's behalf, sending it outside, and so on). *Writing down first the conditions under which you can say the output is finished* makes verification easier.

### 1-3. Drafting with AI

Drafting with AI takes four steps. First, write the request (section 1-1). Next, run the request in a Project (CH06, CH07) or in a chat. Save the output as a *draft* (`_AI_draft`, CH04). Last, ask the AI for a list of the parts that need checking. Do not expect a finished version in one try. Tell the AI which parts are wrong and have it rewrite them, or correct them yourself.

### 1-4. Basic analysis of documents and tables

When you read a table, first look at *what the rows are, what the columns are, and what the unit is*. Four kinds of basic analysis are enough.

A **total** is all the values added together. For example, 1,200 + 1,350 + 1,100 = 3,650. An **average** is the total divided by the count. For example, 3,650 ÷ 3 ≈ 1,217. A **change or ratio** is the difference divided by the starting value. For example, (12,500 − 11,800) ÷ 12,500 = 0.056, which is 5.6%. A **count** is the number of items that meet a condition. For example, the number of decisions with no owner.

> **Author's interpretation** When you ask AI to do an analysis, ask it to *write out the calculation process too* ("Show the formula: which values did you add for the total?"). And **a person recalculates the numbers with a calculator.** AI can get a calculation wrong. This book has not tested whether this way of asking reduces errors.

### 1-5. Separating fact, inference, assumption, and unconfirmed information

Sort each sentence in an AI draft into one of four categories. A **fact** is content written exactly as it is in the source text (notes, material), so you can verify it. An **inference** is a judgment drawn from facts. It sounds plausible but is not written in the source text. An **assumption** is a premise taken as true without checking. **Unconfirmed information** is information that you cannot yet tell is true. The table below gives an example for each, based on the fictional notes, and how to handle it.

| Category | Example (based on the fictional notes) | How to handle it |
|---|---|---|
| Fact | "Manager A opposed the cut" (it is in the notes) | Write it as is |
| Inference | "The price cut seems to have been a burden" (not in the notes) | Mark it as an inference or do not write it |
| Assumption | "Associate B will send it by next Tuesday" (the notes say "by next week") | Mark it as an assumption and check it |
| Unconfirmed | "Date of the next meeting" (the notes say undecided) | Leave it as "Needs confirmation" |

In the final output, write *only facts*. Mark inferences and assumptions so they stand out, and do not leave unconfirmed items blank; write "Needs confirmation." To make AI keep this separation, write it in rule ⑤ of the request.

### 1-6. Verifying numbers and quotations

To verify numbers, first compare them with the numbers in the source text character by character. Next, recalculate totals, averages, and ratios yourself, and check the unit (KRW, units, %).

A **quotation** is copying words or numbers from the source text exactly as they are. For words in quotation marks, search (`Ctrl + F`) to check that they appear in the source text *exactly*. If they do not, it is not a quotation; it is words that were made up.

Check the sources too. If AI writes "according to ...", check that the source is actually inside the input material. Do not trust a source that is not in the input material.

### 1-7. Identifying errors in AI output

A **hallucination** (fabrication) is when AI makes up content that is not in the source text and presents it as fact. This book also calls it "fabrication." Including fabrication, errors in AI output fall into the seven types below.

| Error type | What it looks like | How to find it |
|---|---|---|
| Fabrication | A decision, quotation, or number that is not in the notes | Look up every sentence in the source text |
| Distortion | The meaning changes (a "revised proposal" becomes a "price-cut proposal") | Compare key words with the source text |
| Omission | An item that was there is missing (open items) | Compare the number of items in the source with the number in the result |
| Calculation error | The total, average, or ratio is wrong | Recalculate it yourself |
| Format error | Not the table format you asked for | Compare with request part ④ |
| Overconfidence | States something as certain that is not known | Check where a "Needs confirmation" mark should be |
| Source confusion | Cites a source that is not in the input | Check that the source is in the input material |

### 1-8. The procedure for human final approval

Final approval takes four steps. First, fill in the fact-check table to the end. Next, make a corrected version that fixes the wrong parts. Then the approver writes down *the items checked and the date*. Last, send only the approved file to `03_Final` and share it.

Even if AI wrote it, **the person who approved it is responsible for the content** (this book's position, Author's interpretation). For questions of legal responsibility, ask your organization or legal staff.

## 2. Workplace Application

Gasang Han of the fictional company "Example Trading Co." received an AI-made draft of meeting minutes and was about to share it with the team right away, but first filled in a fact-check table. (Everything is fictional.)

Gasang Han first compared each sentence in the draft with the source text. The sentence "Decided to send the price-cut proposal" differed from the "revised proposal" in the notes (distortion). You are done when all of the following are true.

## 6. Troubleshooting

**When AI writes content that is not in the notes.** The rules in the request are weak, or the input material is vague. Add "Do not write anything that is not in the notes" to request part ⑤ and have a person check the result. This book does not say AI never makes mistakes.

**When the result is different every time.** AI's responses can differ even for the same request. Make the request more specific, and save a result you like as a file to use as a reference.

**When the calculation keeps coming out wrong.** AI can get a calculation wrong. Do the calculation yourself with a calculator, and ask the AI to show the formula.

**When you can't tell how much is fact.** There are no source marks. For each sentence, write which line of the notes it comes from. If you cannot find the basis, do not write the sentence as fact.

**When it says it's wrong even though you copied the source exactly.** The source text itself may be wrong. Check with the person in charge whether the source text itself is correct.

**When there is no one to check.** No approver has been designated. Ask who your organization's approver is. Do not share the output until one is designated.

**When the draft contains personal information.** The personal information was in the input material. Stop using the draft immediately, tell the person in charge, and delete that chat (CH03 section 6).
