## 1. 학습목표

이 장을 마치면 다음을 할 수 있다.

- AI 서비스에 입력한 내용에 대해 *전송*, *저장*, *학습에 사용*이 서로 다른 질문임을 설명할 수 있다.
- 업무자료를 *넣어도 되는 정보 / 가린 뒤 넣는 정보 / 넣지 않는 정보*로 나누고 이유를 말할 수 있다.
- 개인정보, 민감한 정보, 비밀번호, API 키를 AI 서비스에 입력하지 않는 습관을 정할 수 있다.
- 내가 쓰는 AI 서비스(ChatGPT, Claude 등)의 데이터 처리 방식을 공식 문서와 내 계정 설정 화면에서 확인하는 방법을 안다.
- 개인용 계정과 조직용 계정의 차이를 알고, 업무에 어느 계정을 써야 하는지 담당자에게 물어볼 수 있다.
- 가상자료를 만들어 안전하게 연습할 수 있다.
- CH01·CH02에서 정한 후보 업무 A와 그 업무에 쓸 자료를 이 장의 등급으로 검토하고, AI에 넣기 전에 해야 할 일(가리기, 담당자 확인, 넣지 않기)을 정할 수 있다.

> - **필수 학습:** 2-1(전송·저장·학습), 2-2(정보 등급), 2-5(비밀번호·API 키), 2-6(가상자료 만들기), 실습 1·2, 실습 3(내 후보 업무 A의 자료 검토)

## 2. 핵심 개념

**이 장에서 쓰는 말**
- **모델 학습**: AI 서비스 회사가 사용자가 쓴 글을 재료로 삼아 AI를 더 낫게 만드는 일. 공식 문서에서는 "모델 개선(improve the model)"이라고도 부릅니다.
- **API 키**: 프로그램이 AI 서비스에 접속할 때 쓰는 긴 문자열 비밀번호. 이것을 아는 사람은 내 계정으로 서비스를 쓸 수 있습니다.
- **개인용 / 조직용 계정**: 혼자 가입해서 쓰는 계정이 개인용, 회사나 학교가 관리자를 두고 쓰는 계정(공식 문서에서는 Business, Enterprise, Edu, `Claude for Work` 같은 이름)이 조직용입니다. 정확한 이름은 서비스와 시기에 따라 바뀔 수 있습니다.
- **비식별화**: 누구의 정보인지 알아보기 어렵게 바꾸는 것.
- **개인정보**: 살아 있는 사람을 알아볼 수 있는 정보. 이 책에서는 일반적인 뜻으로 쓰며, 법령상의 정의와 범위는 다를 수 있습니다.

### 2-1. 전송, 저장, 학습은 서로 다른 질문이다

대부분의 AI 서비스는 내가 입력한 글이나 파일을 서비스 회사의 시스템으로 보내 처리합니다. 이를 **전송**이라고 합니다. 전송 이후에 일어날 수 있는 일은 서로 다른 세 가지 질문으로 나눌 수 있습니다.

| 질문 | 뜻 | 예 |
|---|---|---|
| 전송되는가? | 내 입력이 서비스 회사에 도착하는가 | 서버에서 동작하는 AI 서비스는 대체로 그렇다 |
| 저장되는가? | 대화 기록 등이 얼마 동안 남는가 | 서비스, 계정 종류, 설정마다 다르다 |
| 학습에 쓰이는가? | 회사가 모델을 개선하는 데 내 내용을 쓸 수 있는가 | 서비스, 계정 종류, 설정마다 다르다 |

> **저자 해석** 흔한 오해는 "학습에 안 쓴다고 했으니 안전하다" 또는 "저장 안 된다고 했으니 보내도 된다"입니다. 학습에 쓰이지 않아도 전송은 일어나고, 저장되지 않아도 전송은 일어납니다. 어떤 정보를 넣을지는 *셋 모두를 따로 확인한 뒤* 정해야 합니다. 공개 저장소 한 곳이 이 구분을 문서 첫머리에서 밝히는 사례를 3절에서 봅니다.

### 2-2. 정보 등급: 세 가지로 나누기

> **저자 해석** 아래 등급은 일반 실무자가 빠르게 판단하도록 저자가 만든 *교육용 기준*입니다. **법적 분류나 공인된 기준이 아닙니다.** 어떤 정보가 법령상 개인정보나 영업비밀에 해당하는지는 회사의 정보보안·법무 담당자에게 확인하세요.

| 등급 | 이름 | 기준 | 예 | 행동 |
|---|---|---|---|---|
| A | 넣어도 되는 정보 | 이미 공개되었거나, 특정인·특정 회사와 관계없는 정보 | 홈페이지에 게시된 소개글, 보도자료 공개본, 일반 상식 질문, 이 책의 가상자료 | 넣어도 된다 |
| B | 가린 뒤 넣는 정보 | 회사 *내부* 업무정보이지만 이름, 금액, 연락처를 빼면 구조만 남는 것 | 회의록, 내부 보고서 초안, 거래처별 조건 | **조직이 허용한 서비스·계정에서만**, 식별 가능한 부분을 가린 뒤에 넣는다 |
| C | 넣지 않는 정보 | 한번 보내면 되돌리기 어렵거나 계약·규정상 보호해야 할 가능성이 큰 정보 | 사람을 알아볼 수 있는 정보가 묶인 목록, 일반적으로 민감하게 다루는 정보, 비밀번호·API 키, 비밀유지 대상 자료, 조직이 금지한 자료 | 넣지 않는다 |

**C 등급의 대표 항목(저자의 예시)**
- 사람을 알아볼 수 있는 정보: 이름과 연락처가 묶인 고객 명단, 주민등록번호 같은 번호, 계좌번호
- 일반적으로 민감하게 다루는 정보: 건강 정보, 개인의 신념이나 가입 단체 같은 사적인 사항 (법령상 "민감정보"의 범위와는 다를 수 있음)
- 접근 수단: 비밀번호, 인증번호, API 키, 접속 주소와 계정이 함께 적힌 메모
- 계약서의 비밀유지 조항(계약 내용을 외부에 알리지 않기로 한 약속)이 걸린 자료, 투자자 배포 전 사업계획서

### 2-3. AI 서비스의 데이터 처리와 보관: 공식 문서에서 확인한 것 (참고 학습)

아래는 2026-10-26에 공식 도움말과 개인정보 안내 페이지를 브라우저로 직접 읽고 정리한 것입니다. 정책과 화면은 자주 바뀌므로, **이 절을 그대로 믿기 전에 내 계정 화면과 공식 문서의 현재 내용을 다시 확인하세요.** 문서에 적혀 있지 않은 것은 추정하지 않았습니다.

> **공식 문서 확인 — ChatGPT (OpenAI), 확인일 2026-10-26**
>
> - 개인용 서비스(Free, Plus, Pro)에서는 사용자의 내용을 모델 학습에 쓸 수 있다. 끄려면 ChatGPT의 설정 > 데이터 제어(Data controls)에서 `Improve the model for everyone`을 끄거나 개인정보 포털(Privacy Portal)에서 `Do not train on my content`를 선택한다. 둘 중 하나로 충분하다. `[S1]`
> - 개인 계정(Free, Plus, Pro)에서는 이 설정이 기본으로 켜져 있다고 데이터 제어 문서가 밝힌다. `[S2]`
> - 이 설정을 꺼도, 응답에 엄지 위/아래 같은 피드백을 보내면 그 피드백과 연결된 대화 전체가 학습에 쓰일 수 있다. `[S1]` `[S2]`
> - 학습 설정을 꺼도 저장된 대화는 지워지거나 숨겨지지 않는다. 대화나 계정은 따로 삭제해야 한다. `[S2]`
> - 임시 채팅(Temporary chat)은 임시 상태인 동안 기록에 나타나지 않고 메모리(AI가 내용을 기억해 두는 기능)를 만들거나 바꾸지 않으며 모델 개선에 쓰이지 않는다. 다만 안전 목적으로 최대 30일간 보관될 수 있다. 저장하면 일반 채팅이 되어 계정 설정을 따른다. `[S1]` `[S2]`
> - ChatGPT Business, Enterprise, Edu와 API는 기본적으로 입력과 출력을 모델 개선에 쓰지 않는다. `[S1]` `[S2]`

> **공식 문서 확인 — Claude (Anthropic), 확인일 2026-10-26**
>
> - 개인 소비자용 제품(Claude Free, Pro, Max, 그리고 그 계정으로 쓰는 개발자용 도구 Claude Code)에서는 ① 사용자가 모델 개선에 쓰도록 허용한 경우, ② 대화가 안전 검토 대상으로 표시된 경우, ③ 그 밖에 학습에 명시적으로 참여한 경우에 대화를 쓸 수 있다. 허용 여부는 개인정보 설정(Privacy Settings)의 `Model Improvement`에서 정한다. `[S3]`
> - 시크릿 대화(Incognito chats)는 `Model Improvement`가 켜져 있어도 모델 개선에 쓰이지 않는다. `[S3]`
> - 엄지 위/아래로 피드백을 보내면 관련 대화 전체가 최대 5년간 보관될 수 있다. `[S3]`
> - 대화를 삭제하면 기록에서 즉시 사라지고 서비스 회사의 서버(문서의 표현은 "백엔드 저장소")에서는 30일 이내에 삭제된다. `[S4]`
> - 모델 개선을 허용한 경우 비식별화된 형태로 최대 5년까지 모델 학습 과정에 보관될 수 있다(허용 이후의 새 대화나 재개한 대화에 적용). 허용을 끄면 이전 대화와 새 대화를 앞으로의 학습에 쓰지 않지만, 이미 진행 중인 학습이나 이미 학습된 모델에 들어간 데이터는 남는다. `[S4]`
> - 이용 정책 위반으로 자동 시스템에 표시된 대화는 입력과 출력을 최대 2년간 보관할 수 있다. `[S4]`
> - 업무용 상품(Claude for Work, Anthropic API 등)은 기본적으로 입력과 출력을 모델 학습에 쓰지 않는다. 다만 피드백을 보내거나 사용자가 허용한 경우는 예외다. `[S5]`

**이 장에서 확인하지 못한 것 (추정하지 않음)**
- Claude 개인용 제품에서 `Model Improvement`의 *기본값*이 무엇인지는 읽은 문서에 적혀 있지 않았습니다. 내 계정 설정 화면에서 현재 상태를 직접 확인하세요.
- ChatGPT Business·Enterprise·Edu와 Claude for Work의 *대화 보관 기간*과 관리자 설정 세부 내용은 읽지 않았습니다. OpenAI 문서는 관리형 워크스페이스에 조직 단위의 보관·메모리·접근 설정이 있을 수 있다고만 밝힙니다 `[S2]`. 조직의 관리자에게 확인하세요.
- 요금제별 세부 차이, 지역별 차이, 이 글을 읽는 시점 이후의 변경은 확인하지 않았습니다.

### 2-4. 개인용 계정과 조직용 계정 (참고 학습)

> **공식 문서 확인 — 업무용 제품의 기본값, 확인일 2026-10-26**
>
> - 두 회사 모두 문서에서 업무용(조직용) 제품은 기본적으로 입력과 출력을 모델 학습에 쓰지 않는다고 밝힌다. `[S1]` `[S2]` `[S5]`

> **저자 해석** 그렇다고 "조직용이면 무엇이든 넣어도 된다"는 뜻은 아닙니다.
>
> - 조직용 계정에서도 *어떤 자료를 넣을 수 있는지*는 회사 규정이 정합니다.
> - 회사 업무 자료를 *개인 계정*에 넣는 것은 회사 규정 위반이 될 수 있습니다. 회사가 어느 서비스·어느 계정을 허용하는지 먼저 물어보세요.
> - 개인 계정이라면 학습 설정과 대화 삭제 방법을 스스로 확인해야 합니다(5절 실습 4).
> - 조직 계정에서 설정 메뉴가 안 보이는 것은 관리자가 관리하기 때문일 수 있습니다. 사용할 수 있는 설정이 계정 종류와 워크스페이스 설정에 따라 달라질 수 있다고 OpenAI 문서가 밝힙니다 `[S2]`.

### 2-5. 비밀번호와 API 키 지키기

비밀번호와 API 키는 *열쇠*입니다. 열쇠가 적힌 글을 남에게 보내면 열쇠를 건넨 것과 같습니다.

> **저자 해석** 지켜야 할 습관(일반적인 보안 권고이며 특정 서비스의 공식 지침이 아닙니다)
>
> 1. 비밀번호, 인증번호, API 키를 AI 서비스에 붙여 넣지 않는다. 오류 메시지나 설정 파일을 붙여 넣을 때도 그 안에 열쇠가 섞여 있는지 먼저 본다.
> 2. 열쇠를 파일 이름, 메모 앱의 제목, 화면 캡처에 남기지 않는다.
> 3. 비밀번호는 비밀번호 관리 프로그램에 보관하고, 가능한 서비스에는 2단계 인증(비밀번호 외에 휴대폰 인증 등을 한 번 더 요구하는 방식)을 켠다.
> 4. 열쇠를 어디에 입력했는지 의심스러우면 *이미 노출된 것으로 보고* 해당 서비스에서 즉시 폐기하고 새로 만든다. (발급 서비스마다 화면이 다르므로 그 서비스의 안내를 따른다.)

### 2-6. 안전한 가상자료 만들기

연습이나 시연에는 실제 자료 대신 *구조는 같고 내용은 가짜인* 자료를 씁니다.

| 바꿀 것 | 이렇게 바꾼다 |
|---|---|
| 사람 이름 | 가나다, 라마바, 담당자A 같은 표시 |
| 회사 이름 | 예시상사, A사, B사 |
| 금액·수량 | 실제와 다른 어림수 |
| 연락처 | `010-0000-0000`, `example@example.com` |
| 날짜 | 대략적인 시기 또는 가상의 날짜 |
| 주소, 계좌, 번호 | 쓰지 않거나 `○○○`로 표시 |

가린 뒤에도 *누구의 이야기인지 짐작되면* 안 됩니다. 업계에서 한 곳뿐인 특이한 사건처럼 내용 자체가 식별 정보인 경우도 있습니다.

## 3. 업무 적용 사례

가상의 회사 '예시상사'의 한가상 씨가 AI에 넣고 싶어 한 자료 세 가지를 등급으로 나눠 봅니다. (모두 가상, 등급은 저자의 교육용 판단)

| 상황 | 자료 | 등급과 판단 |
|---|---|---|
| 회의록을 정리하고 싶다 | 내부 회의 메모(참석자 이름, 금액 포함) | **B.** 이름과 금액을 가린 뒤, 회사가 허용한 서비스·계정에서만 |
| 고객 안내문을 쓰고 싶다 | 고객 명단(이름+연락처) | **C.** 명단은 넣지 않는다. 안내문 *양식*만 만들고 이름 자리는 `[고객명]`으로 두어, 명단은 PC에서 직접 채운다 |
| 시스템 접속 오류를 물어보고 싶다 | 접속 정보가 적힌 메모 | **C.** 비밀번호는 절대 넣지 않는다. 오류 메시지만 따로 옮기되 그 안에 열쇠가 섞이지 않았는지 확인한다 |

> **하네스 사례 — 저장하지 않아도 전송은 일어난다는 점을 처음부터 밝힌 고객발굴 하네스**
>
> - 저장소: rando-client-discovery-harness
> - 파일 경로: `docs/privacy.md`(0절), `HARNESS.md`(9절), `README.md`
> - 확인한 내용: 업로드한 원본을 서버에 영구 저장하지 않는 것을 기본값(`storage_mode = EPHEMERAL`, 처리가 끝나면 원본을 지우는 방식)으로 한다. 다만 `docs/privacy.md` 0절은 "저장하지 않는 것"과 "전송하지 않는 것"이 다르다고 밝히며, README는 추출된 텍스트가 설정한 AI 서비스 회사(문서의 표현은 "LLM Provider")에게 전송된다고 적는다. `HARNESS.md` 9절은 실제 고객 정보, 개인정보, API 키, 비공개 제안서를 공개 저장소에 올리지 않고 예제와 테스트 자료는 완전히 가상의 정보만 쓴다고 정한다.
> - 진행 상태: 공개 저장소. README 기준 버전 0.7.0-alpha.1(9단계 중 7단계). 아직 완성품이 아니다.
> - 확인일: 2026-10-26

> **저자 해석** 이 사례에서 가져올 교훈은 코드가 아니라 *태도*입니다. 문서는 "저장하지 않는다"고 말하는 데서 멈추지 않고 "그래도 전송은 된다"를 같이 밝힙니다. 이 장의 2-1절과 같은 구분입니다.

## 4. 준비물

- 계정·권한·비용: 필요 없음. (5절의 *실습 4*는 이미 쓰고 있는 AI 서비스의 설정 화면을 *읽기만* 합니다. 설정을 바꾸는 것은 선택이며, 조직 계정이라면 관리자에게 먼저 묻습니다.)
- 프로그램·파일: 메모 도구, 이 장의 가상자료(5절에 모두 들어 있음), 인터넷 브라우저(9절의 공식 문서를 읽을 때). **내 실제 업무 파일은 이름과 종류만 봅니다. 내용을 열지 않고, AI 서비스에 입력하지도 않습니다.**
- 선수학습: CH01의 후보 업무 A와 AI와 함께 수행하려는 목적, CH02의 구성도와 데이터 이동 표. 없으면 AI에게 맡기고 싶은 업무 하나와 그 업무에 쓸 자료의 이름, 내가 쓰는 AI 서비스 이름과 개인용인지 조직용인지만 알면 됩니다.
- 소요 시간: 약 50분(저자의 예상이며 실제 학습자에게 시험해 보지 않았습니다)

**실습 이름: 정보 등급표 만들기**

- **시작 상태:** CH01의 후보 업무 A와 목적, CH02의 구성도와 데이터 이동 표가 있다.
- **완료 상태:** ① 가상 파일 12개를 등급으로 분류한 표, ② 가상 메모를 가린 결과, ③ 후보 업무 A의 자료 검토표(필수), ④ 내가 쓰는 AI 서비스 확인표 1개 이상(참고), ⑤ 내 업무 파일 종류별 등급표와 "넣지 않는 것" 목록(참고)이 있다.
- **안전 원칙:** 어느 실습에서도 실제 개인정보, 고객자료, 비밀번호, API 키를 AI 서비스에 입력하지 않습니다. 실습 3~5에서 내 실제 자료는 *이름과 종류만* 적습니다.


## 7. 오류 해결

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| 내 화면의 메뉴 이름이 문서와 다르다 | 요금제, 앱 버전, 지역, 조직 설정에 따라 화면이 다를 수 있다 | 문서의 확인일을 보고, 내 화면의 설명을 우선한다. 확실하지 않으면 "모름"으로 적고 담당자에게 묻는다. 화면과 문서가 다른데도 문서대로라고 단정하지 않는다 |
| 조직 계정인데 학습 설정 메뉴가 없다 | 사용할 수 있는 설정은 계정 종류와 워크스페이스 설정에 따라 달라질 수 있다 `[S2]`. 관리자가 관리하고 있을 가능성이 있다 | 관리자에게 보관 기간과 학습 사용 여부를 문의한다 |
| 이미 민감한 내용을 입력해 버렸다 | 등급을 정하기 전에 사용했다 | 숨기지 말고 아래 순서로 한다. ① 조직 자료라면 담당자에게 알린다 ② 그 서비스에서 해당 대화를 삭제한다 — 학습 설정을 끄는 것만으로는 저장된 대화가 삭제되지 않는다 `[S2]`. Claude는 삭제하면 기록에서 즉시 사라지고 서비스 회사 서버에서 30일 이내에 삭제된다고 안내한다 `[S4]` ③ 비밀번호나 API 키였다면 해당 서비스에서 즉시 폐기하고 새로 만든다 |
| 학습 설정을 껐는데 불안하다 | 피드백 등 예외가 있다 | 엄지 위/아래 같은 피드백을 보내면 해당 대화가 학습이나 장기 보관에 쓰일 수 있다는 점을 기억한다 `[S1]` `[S3]`. 민감한 대화에서는 피드백을 보내지 않는다 |
| 가렸는데도 누구 이야기인지 알 것 같다 | 내용 자체가 식별 정보다 | 사건의 특징(시기, 지역, 금액)까지 일반화하거나, 그 자료는 C로 취급한다 |
| 어느 등급인지 판단이 안 선다 | 기준이 애매하다 | 더 보수적인 등급을 고르고 담당자에게 묻는다. 확인되기 전에는 넣지 않는다 |
